# 실행 로그

> 대화 전문은 편집하지 않고 원문 그대로 붙인다. 화자 표기(`User:`, `AI:`)와 턴 번호만 덧붙였다.
> 복사 과정에서 붙은 화면 문구("내보내기", "직접 또는 Gemini로 수정 ..." 안내)는 응답 내용이 아니라서 지웠다. 이 외에는 고치지 않았다.
> 표시 방법: 환각은 해당 줄 끝에 `[환각]`, 문맥 끊김은 `[문맥 끊김]`을 붙인다. 둘 다 없으면 없다고 적는다.

## 1. 작업 기록
작업 하나를 한 항목으로 적는다. 무엇을 어떻게 했는지가 드러나게 쓴다.

- 과업 정의: 변경 메모를 "기존 상황, 변경 내용, 결과" 구조의 변경 기록 md로 정리하는 과업으로 정하고, 타겟 사용자와 입력, 출력 규격을 문장으로 적음
- 문서 틀 작성: `docs/` 아래에 비교 보고서, 설계 문서, 실행 로그, 미해결 기록 네 문서의 틀을 요구사항 항목대로 만듦
- 샘플 입력 선정: 실제 업무 내용을 빼기 위해 주문 조회 API의 totalPrice 타입 변경이라는 가상의 변경 사례를 정함
- 페르소나와 시스템 프롬프트 작성: 이름, 역할, 전문 분야, 말투, 금지 사항, 우선순위 여섯을 정하고 시스템 프롬프트와 입력 템플릿으로 옮김
- 모델 3종 1차 비교: 클로드, 제미나이, 챗지피티의 새 대화창에 같은 프롬프트와 주문 API 샘플을 넣고 응답 원문을 저장함
- 모호한 입력 2차 비교: 같은 시스템 프롬프트에 "쿠폰 로직을 고쳤다."를 넣어 세 모델이 문서를 쓰기 전에 되묻는지 확인함
- Zero-shot 12턴 대화: 세 모델에 3턴부터 12턴을 진행하며 날짜 형식 조건 변경, 환각 검증 질문 6개, 같은 입력 반복을 넣고 원문을 저장함
- 점수 매기기: 형식 준수, 사실 보존, 누락, 지시 재확인 네 기준으로 모델별 점수와 근거를 적고 합계를 계산함(클로드 20, 제미나이 19, 챗지피티 17)
- 모델 선정: 주로 쓰는 AI이고 평가 기준에서도 가장 높아 클로드로 정하고 이유를 적음
- Few-shot 프롬프트 작성: 예시 3건(정상, 일부 정보 없음, 되묻기)을 입력과 출력 한 쌍으로 만들어 시스템 프롬프트에 붙이고, 같은 샘플로 한 번 실행해 Zero-shot 결과와 비교함
- 단계적 추론 유도 결정: 넣지 않아도 이미 충분한 결과를 내고 있어 추가하지 않기로 함
- Few-shot 12턴 대화 재진행: 메모리가 켜진 대화에서 5턴 조건을 받기 전에 날짜 형식이 이미 바뀐 것을 발견해, 완전히 새로운 세션에서 12턴을 다시 진행하고 이전 대화는 참고용으로 남김
- 환각 질문 판정: 7개 질문(수정일, 엔드포인트, 파일 수, 타입, 테스트 건수, 담당자, 화면 이름)의 답을 정답과 대조해 모두 Pass로 판정함
- 로그 표시: 환각과 문맥 끊김이 나타나지 않았음을 적고, 5턴과 11턴 반복 입력에서 6턴과 12턴 문서가 같았음을 기록함
- v2 작성과 실행: 12턴 4턴 문서에서 입력에 있는 확인 내용을 "확인 필요"로만 적던 문제를 고치려고 규칙 5를 추가하고, 새 세션에서 실행해 확인 방법이 채워지는 것을 확인함
- 미해결 과업 시도: 변경 메모 5건을 하나의 문서로 묶는 과업을 정답표와 대조했고, 프롬프트를 고치지 않고 1차에 성공해 미해결로 적지 않음
- 미해결 기록 정리: 프롬프트를 고쳐도 해결하지 못한 과업이 없음을 적고, 코드 변경 설명과 MCP 자동 기록은 아직 시도하지 않은 향후 확장 계획으로 따로 적음
